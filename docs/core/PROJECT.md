# Core spec: Project Launch Copilot for MWS Tables

Статус: **baseline**. Это стабильный контракт проекта, составленный по условиям кейса. Рабочие гипотезы и детали будущей реализации сюда не добавляются.

## Контекст

Новые проектные инициативы поступают через формы, файлы и ручной ввод в MWS Tables. До запуска менеджер проектного офиса вручную проверяет и исправляет данные, ищет дубли, связывает справочники, классифицирует проект, проверяет бюджет и сроки, создаёт задачи и назначает исполнителей.

Модельный поток — 200 новых или изменяемых заявок в месяц по 50 минут ручной работы. Это около 167 часов и 330 000 рублей в месяц при полной стоимости часа 2 000 рублей.

## Пользователи

- менеджер проекта;
- администратор проектного офиса;
- руководитель операционного подразделения.

## Требуемый результат

Рабочий JavaScript Widget Script, установленный в предоставленном пространстве MWS Tables. Пользователь без знания JavaScript должен выбрать представление или записи и пройти сквозной сценарий:

1. анализ качества данных;
2. preview и подтверждение исправлений;
3. поиск дублей;
4. сопоставление со справочниками;
5. создание связей;
6. формирование проекта и связанных задач;
7. рекомендации исполнителей;
8. итоговый отчёт.

Команда также передаёт исходный код, инструкцию по установке/настройке, описание алгоритмов, результаты тестирования и короткую демонстрацию.

## Обязательные возможности

- Конфигурируемый выбор таблиц и полей без жёсткой привязки к ID.
- Нормализация email, телефона, пробелов, символов, регистра, `е/ё`, дат, городов, компаний и ФИО.
- Поиск дублей и справочных соответствий по нескольким признакам с оценкой совпадения.
- Объяснимая рекомендация: исходное и предлагаемое значение, причина и уверенность.
- Подтверждение или отклонение отдельных действий до записи данных.
- Связи через Two-way Link, One-way Link, Lookup и подходящие типы полей.
- Выбор шаблона проекта, создание задач и рекомендации исполнителей.
- Понятная обработка ошибок и итоговая сводка запуска.
- Углублённая реализация хотя бы одной интеллектуальной функции из условий кейса.

## Ограничения и инварианты

- Реализация выполняется на JavaScript внутри Widget Script MWS Tables.
- Исходные записи не удаляются.
- Массовые изменения выполняются только после preview и подтверждения.
- Повторный запуск идемпотентен: не создаёт повторные задачи или связи.
- Базовые очистка, matching и создание задач работают без LLM.
- Внешний LLM API необязателен; endpoint, модель и токен задаются конфигурацией.
- Секреты не хранятся в исходном коде.
- Данные отправляются наружу только после явного действия пользователя.
- Полноценный backend, промышленная нагрузка, отдельная авторизация и интеграции с боевыми системами не требуются.

## Метрики успеха

- Не менее 70% заявок готовы к запуску после одного запуска без ручного редактирования отдельных ячеек.
- Медианное время подготовки заявки — не более 10 минут вместо 50.
- Точность предложений по дублям и matching — не менее 90%.
- Обнаружение не менее 80% заложенных дублей и ошибок.
- 100% массовых изменений имеют preview и требуют подтверждения.
- Повторный запуск создаёт 0 повторных связей и задач.

## Вне scope

- полноценная система управления проектами;
- промышленная эксплуатация и обработка миллионов записей;
- собственная большая языковая модель;
- глубокая реализация всех интеллектуальных модулей одновременно;
- полное устранение человека из неоднозначных решений;
- работа с реальными конфиденциальными данными;
- публикация в общем каталоге виджетов.

## Риски и открытые вопросы

- Фактический API MWS Tables может отличаться от публичной документации AITable.
- Эталонная разметка организаторов недоступна команде и потребует отдельного протокола оценки.
- Структура связанных таблиц и UX подтверждения должны быть согласованы с заказчиком.
