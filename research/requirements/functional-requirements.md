# Functional Requirements — Project Launch Copilot

## 1. Настройка обработки
Система должна позволять пользователю:
- выбрать таблицу, представление или набор записей для обработки;
- выбрать поля для анализа;
- выбрать таблицы справочников компаний, сотрудников, проектов, шаблонов задач;
- сохранить или повторно использовать конфигурацию обработки.

## 2. Анализ и нормализация данных
Система должна:
- проверять выбранные записи на ошибки и подозрительные значения;
- приводить email к нижнему регистру;
- приводить телефоны к единому формату;
- удалять лишние пробелы и служебные символы;
- нормализовать регистр, `е/ё`, варианты написания;
- приводить даты к единому формату;
- нормализовать названия городов, компаний и ФИО;
- отмечать неполные и потенциально некорректные записи.

## 3. Поиск дублей и matching
Система должна:
- искать вероятные дубли внутри входящих заявок;
- искать соответствия со справочниками компаний, сотрудников и проектов;
- использовать несколько признаков: название, ИНН, email, телефон, город и др.;
- рассчитывать confidence score;
- разделять уверенные и неоднозначные соответствия;
- предлагать массовое применение только для high-confidence кейсов;
- передавать ambiguous cases пользователю на review.

## 4. Preview изменений
Система должна:
- показывать для каждого действия исходное и предлагаемое значение;
- показывать тип изменения;
- показывать confidence score;
- показывать причину рекомендации;
- позволять принять или отклонить отдельные действия;
- поддерживать массовое подтверждение части рекомендаций.

## 5. Создание связей и сущностей
После подтверждения система должна:
- записывать подтверждённые исправления;
- создавать связи между заявками и справочниками;
- при необходимости создавать проект на основе заявки;
- выбирать шаблон задач;
- создавать набор задач, связанных с проектом;
- предлагать исполнителей для задач.

## 6. Проверка после связывания
Система должна поддерживать повторную проверку уже связанного набора данных:
- на межтабличную целостность;
- на отсутствие незакрытых неоднозначных соответствий;
- на корректность критичных связей перед запуском.

## 7. Итоговая сводка
После применения изменений система должна:
- показать количество обработанных записей;
- показать количество исправлений;
- показать количество созданных связей;
- показать количество найденных дублей;
- показать количество аномалий и неоднозначных кейсов;
- показать количество созданных задач.

## 8. Расширенные функции
Система должна быть спроектирована так, чтобы поддерживать:
- загрузку из JSON и внешних систем;
- визуальную карту связей;
- LLM-проверку неоднозначных случаев;
- классификацию заявки по тексту;
- поиск аномалий;
- накопление правил на основе пользовательских подтверждений.
