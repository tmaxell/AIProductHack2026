# Как проверить веб-приложение

Пошаговый прогон всех реализованных функций с ожидаемыми числами. Числа
приведены для демонстрационного набора `data/raw/dev-sample.csv` и первых
100 заявок — именно столько разбирает интерфейс за один прогон.

## Запуск

```bash
cd solution/webapp
make up
```

Приложение — <http://127.0.0.1:8080>, документация API —
<http://127.0.0.1:8080/api/v1/docs>.

Проверка, что стенд поднялся:

```bash
curl -s http://127.0.0.1:8080/api/v1/health
```

Ожидается `referenceCompanies: 1400`, `knownApplications: 6800`,
`storedChangeSets: 0` на чистом стенде.

Сбросить историю версий и начать с нуля:

```bash
make down && docker compose down --volumes && make up
```

## 1. Область запуска

**До запуска** панель справа показывает `Источник — дев выборка · первые 100 из 6800`.

- Отметьте несколько строк чекбоксами слева — подпись меняется на
  `выбрано N из 30`, и проверяться будут только они.
- Снимите отметки — снова первые 100 записей выгрузки.
- `Настройки проверки` показывают текущую область и список полей. Снятая
  галка **исключает поле из проверки**, а не прячет его с экрана.

## 2. Проверка данных

Нажмите **Проверить данные**. Ожидается:

| Показатель | Значение |
|---|---|
| Заголовок | `первые 100 из 6800 записей · 1077 предложений` |
| Готовы к запуску | 96% (96 из 100) |
| Безопасные исправления | 1077 |
| Требуют внимания | 38 |
| Блокирующие ошибки | 4 |
| Сопоставлено с компанией | 91 из 100 |
| Найдено дублей | 12 групп |

Ниже — схема связей `Заявки → Компании` и `Заявки ⇢ Возможные дубли`.

## 3. Выборочное подтверждение

**Посмотреть изменения** открывает отчёт: 29 страниц, 16 правил.

Проверьте:

- у каждой строки свой чекбокс, в шапке — переключатель всего правила
  с промежуточным состоянием;
- футер показывает `Подтверждено N из 1077`, кнопка — точное число;
- снимите пару галок → число уменьшается, и эти значения останутся исходными;
- стрелки `←` `→` листают правила, у крупных правил видно `страница X из Y`.

Правила, у которых нет пары «было → станет», показываются иначе — кандидат,
уровень уверенности и признаки совпадения:

- **Компания из справочника** — колонки `Компания справочника`, `Уверенность`,
  `Совпало по` (например `ИНН, email, телефон, название, город`);
- **Возможный дубль заявки** — колонка `Заявка-оригинал`, признаки включают
  `название проекта` и размер группы.

## 4. Публикация и версии

**Применить N** сохраняет решения и публикует версию. Ожидается
`Версия опубликована · 1077 изменений в 100 записях · разобраны первые 100 из 6800`.

**Версии** в шапке панели открывают историю:

- `Версия #1 · Опубликована`;
- список действий страницами по 50 с кнопками `Назад` / `Далее`;
- append-only история событий: `draft.created`, `decisions.saved`, `published`;
- `Сравнить с` — diff двух версий.

**Подготовить откат** создаёт `Rollback Draft #2` с обратными действиями:
в отчёте `Откат: Email компании`, где `было` и `стало` поменялись местами.
Откат тоже проходит через подтверждение — данные меняются только после него.

## 5. Идемпотентность

Запустите **Проверить снова** после публикации: предложений должно стать 0 —
повторный прогон не создаёт повторных изменений.

## 6. AI Copilot

Кнопка **AI** в шапке панели открывает чат.

**Без ключа Groq** (состояние по умолчанию) панель честно отвечает
`AI-объяснение не настроено: на backend отсутствует GROQ_API_KEY`. Весь
остальной сценарий при этом работает — это требование кейса.

**С ключом**: создайте `.env` из `.env.example`, заполните `GROQ_API_KEY`,
перезапустите `make up`. Тогда:

- три готовые кнопки — «Основные проблемы», «Риски», «Перед публикацией»;
- своё сообщение до 500 символов уходит как «Задача оператора»;
- ответ содержит `summary`, `evidence`, `risks`, `openQuestions`,
  `recommendedActions` — схема проверяется локально;
- блок `Охват` показывает, сколько действий покрыто агрегатом и сколько
  примеров реально отправлено;
- `Что использовал AI` раскрывает перечень полей и модель;
- история попыток сохраняется и видна в версии.

Проверить, что подтверждения не теряются: подтвердите часть изменений,
задайте вопрос Copilot, вернитесь в отчёт — число подтверждённых прежнее.

## 7. Проверка через API

```bash
# метаданные выгрузки
curl -s http://127.0.0.1:8080/api/v1/dataset-snapshots/current

# первые записи страницами
curl -s "http://127.0.0.1:8080/api/v1/dataset-snapshots/current/records?limit=2"

# разбор первых 100 записей
curl -s -X POST http://127.0.0.1:8080/api/v1/dataset-snapshots/current/change-sets \
  -H 'content-type: application/json' -d '{"limit":100}'

# действия версии с фильтром и агрегатами
curl -s "http://127.0.0.1:8080/api/v1/change-sets/<id>/actions?limit=5&ruleCode=budget"

# объяснение областью, а не перечислением действий
curl -s -X POST http://127.0.0.1:8080/api/v1/change-sets/<id>/explanation-preview \
  -H 'content-type: application/json' -d '{"scope":"not-rejected"}'
```

Конфликт исходных данных проверяется так: получите `sourceFingerprint`,
измените запись, попробуйте применить — ответ `409`.

```bash
cd solution/webapp && make check
```

## Известные ограничения

- **Разбирается 100 записей за прогон.** Полная выгрузка даёт около 72 000
  действий, и решения по ним не помещаются в тело запроса. Снятие
  ограничения требует массовой формы решений, см.
  [ADR 0003](adr/0003-full-export-analysis-and-action-pagination.md).
- **Итоговый отчёт запуска считается по 30 встроенным записям**, а не по
  разобранным 100: план задач и назначение исполнителей пока живут на
  фронтенде. Числа в нём не сходятся с числами панели — это ожидаемо.
- **Задачи по шаблону и назначение исполнителей** — демонстрационные,
  round-robin, без учёта загрузки и SLA.
- **Ответ Groq на реальном ключе не проверялся** — стенд поднимался без
  `GROQ_API_KEY`.
