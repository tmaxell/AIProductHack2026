# ADR 0002: Groq как необязательный слой объяснения Change Set

- Статус: принято
- Дата: 2026-09-06

## Контекст

Change Set API уже является источником истины для preview, пользовательских
решений, публикации, конфликтов и rollback. Нужна LLM-функция, которая помогает
понять выбранные изменения, риски и открытые вопросы, но не меняет
детерминированный сценарий и не получает полномочий на запись.

Исходные строки могут содержать персональные данные и произвольный текст.
Внешний вызов допустим только после явного действия пользователя, а ключ Groq
не должен попадать в браузер, SQLite, логи или git. В UI таким действием
является само нажатие «AI-объяснение»: отдельного промежуточного submit нет.

## Решение

Backend вызывает OpenAI-compatible Groq Chat Completions API по HTTPS. Провайдер
использует настраиваемые endpoint и model, по умолчанию strict Structured
Outputs с JSON Schema, локальную проверку ответа, timeout и ограниченные повторы
для `429` и `5xx`. Режим можно переключить на best-effort или JSON Object для
совместимой модели, не ослабляя локальную валидацию. Интеграция считается
доступной только при наличии `GROQ_API_KEY`.

Для сохранённой версии вводятся три операции:

1. явный запрос объяснения для выбранных действий;
2. сохранённый disclosure фактически отправленного маскированного payload;
3. чтение истории сохранённых попыток и результатов.

Перед отправкой backend строит минимизированный документ, который сохраняется и
показывается UI вместе с результатом. В него входят только свойства действий: тип,
правило, поле, решение, результат, причина, уровень уверенности, evidence и
маскированные `before`/`after`. Полные source records не отправляются.
Идентификаторы записей заменяются стабильными локальными псевдонимами.
Email, телефоны, ФИО и похожие персональные поля маскируются; секреты и
внутренняя конфигурация не включаются.

Модель возвращает объект:

- `summary`;
- `evidence[]`;
- `risks[]`;
- `openQuestions[]`;
- `recommendedActions[]`.

Все поля обязательны, объекты закрыты через `additionalProperties: false`.
Ответ повторно валидируется backend. Текст исходных действий передаётся как
недоверенные данные, а системная инструкция запрещает исполнять содержащиеся в
них команды.

## Хранение и аудит

Forward-only миграция добавляет `change_set_explanations`. Каждая попытка
сохраняет:

- Change Set и выбранные action id;
- `pending → completed/failed`;
- model и prompt version;
- перечень раскрытых полей и фактически отправленный маскированный payload;
- структурированный ответ либо безопасный код/текст ошибки;
- время создания и завершения.

Ключ и заголовки авторизации не сохраняются. Запись попытки и результата
создаёт события в append-only истории Change Set.

## Права и отказоустойчивость

LLM не получает tools/function calling и не может вызвать publish, rollback
или изменить решения. Рекомендованное действие остаётся обычным текстом.
Ошибка, timeout, исчерпание rate limit или невалидный ответ не меняют Change
Set и не блокируют его детерминированную публикацию. Пользователь может
повторить объяснение отдельным явным действием.

## Дополнение: prompt version `change-set-copilot-v2`

Работа с полной выгрузкой изменила три вещи в этом ADR.

**Задача оператора.** Запрос принимает необязательное поле `instruction` — до
500 символов свободного текста. Оно передаётся отдельной строкой «Задача
оператора» и намеренно **не** включается в сериализованный payload: системная
инструкция объявляет payload недоверенными данными, и держать одну и ту же
строку одновременно в доверенной и недоверенной роли нельзя. В сохранённом
disclosure инструкция остаётся — согласие должно быть проверяемым.

**Агрегат и выборка.** Change Set по выгрузке содержит тысячи действий, и
целиком в модель они не отправляются. В payload добавлен `coverage` — счётчики
по правилам, решениям и результатам **по всему выбранному набору**, — а поле
`actions` остаётся ограниченной выборкой примеров. Примеры отбираются по кругу
правил, а не подряд: сортировка по коду правила давала перекос в пользу
алфавитно первого правила и обедняла disclosure, потому что `fields`
перечисляет только те поля, значения которых реально ушли.

**Область вместо перечисления.** Запрос принимает `scope` (`accepted` или
`not-rejected`) наряду с `actionIds`. Перечисление идентификаторов десятков
тысяч действий не проходит ограничение размера тела запроса, а сам список
backend может собрать сам: сохранённая версия и есть источник истины. Пустая
область отклоняется `422` и не доходит до модели.

## Последствия

- Groq — заменяемый инфраструктурный адаптер за application-интерфейсом.
- Без ключа весь Change Set flow работает, UI показывает недоступность AI.
- Маскированный payload хранится ради проверяемости согласия; это увеличивает
  SQLite, но не дублирует исходные строки.
- Строгая схема ограничивает модели: совместимая модель задаётся конфигурацией,
  а смена модели не требует изменения API приложения.
