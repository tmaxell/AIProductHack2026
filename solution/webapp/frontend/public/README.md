# Frontend веб-приложения Project Launch Copilot

Статический фронтенд без сборки: оболочка в визуальной грамматике MWS Tables и
панель виджета, которая показывает предложенные изменения, даёт подтвердить или
отклонить каждое из них, публикует версию и умеет откатывать.

Это mock оболочки MWS Tables, а не установленный Widget Script. Решение,
встраиваемое в реальные MWS Tables, — отдельный трек, граница описана в
[`solution/README.md`](../../../README.md).

## Запуск

Фронтенду нужен backend, поэтому штатный способ — весь стек в Docker:

```bash
cd solution/webapp && make up
```

Приложение — <http://127.0.0.1:8080>. Открытый как файл `index.html` работать не
будет: запросы к `/api/v1` идут через nginx.

## Где считается что

Это важно понимать при чтении кода: расчётов два, и они не равноправны.

**Backend — источник истины.** Набор изменений, решения, публикация, конфликты,
версии и откат живут только там. Всё, что пользователь подтверждает и
публикует, приходит из `POST /api/v1/change-sets` и уходит в `/publish`.

**Локальный расчёт — только подсказки.** `engine.js`, `widget-script.js` и
`launch.js` продолжают считать на клиенте:

- показатели сводки, когда проверяются выбранные строки, а не выгрузка целиком;
- сопоставление сотрудников и классификацию типа проекта;
- план задач и назначение исполнителей для итогового отчёта запуска.

**Эти подсказки не сохраняются и не публикуются.** Отсюда расхождение, о
котором стоит знать: итоговый отчёт запуска считает по 30 встроенным записям, а
панель — по разобранным из выгрузки. Числа в них не сходятся, и это ожидаемо.
Перенос этих расчётов в backend — отдельная задача.

## Сценарий

1. **Область.** Без отметок разбираются первые 100 записей выгрузки — панель
   пишет «первые 100 из 6800». Отмеченные строки сужают область до них.
2. **Проверка.** `POST /api/v1/change-sets` или
   `/dataset-snapshots/current/change-sets` возвращает draft. Ничего не пишется.
3. **Решения.** В отчёте у каждого действия свой чекбокс, в шапке таблицы —
   переключатель правила. Панель и футер показывают «Подтверждено N из M».
4. **Спорные значения.** Если правила чего-то не восстановили, в панели
   появляется блок с кнопкой разбора через AI — единственное место, где эти
   значения уходят наружу, и только по нажатию.
5. **Публикация.** Применяются только подтверждённые действия, включая
   предложения AI. Версия переходит в `published`.
6. **Версии и откат.** История, diff, компенсирующий rollback-draft, который
   сам проходит через подтверждение.

## Состояния панели

| Состояние | Что показывает |
|---|---|
| До запуска | источник и область, один CTA «Проверить данные» |
| Выполняется | спиннер и disabled-кнопка |
| Результат | счётчики, схема связей, блок спорных значений, ссылка на отчёт запуска |
| Опубликовано | что изменено по правилам и «Подготовить откат» |
| Ошибка | причина и «Повторить»; запрос не висит дольше 20 секунд |

## AI-панель

Кнопка **AI** в шапке. Панель отвечает на вопросы о текущей версии: что
меняется, что рискованно, каким сопоставлениям не доверять, что проверить перед
публикацией. Стартовое сообщение перечисляет, что модель видит и чего не видит.

Модель не может ничего применить или опубликовать. Исходные строки целиком не
передаются: идентификаторы записей заменяются псевдонимами, контакты и ФИО
маскируются. Без ключа Groq панель честно сообщает причину, а весь остальной
сценарий работает.

## Чего пока нет

Из обязательного сквозного сценария
[`docs/core/PROJECT.md`](../../../../docs/core/PROJECT.md) не реализованы связи
через Link/Lookup и сохраняемые в backend задачи с исполнителями. Итоговый
отчёт запуска показывает их демонстрационно, round-robin, без учёта загрузки
и SLA.
