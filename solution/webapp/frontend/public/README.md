# Mock MVP — Project Launch Copilot для MWS Tables

Статический демонстрационный фронтенд: оболочка в визуальной грамматике MWS Tables
и панель виджета, которая проверяет форматы данных заявки и показывает список
изменений `было → стало` до их применения.

Это mock, а не установленный Widget Script. Оболочка воспроизводит пропорции и
визуальный язык платформы, но не является её точной копией и ни к чему не подключена.

## Запуск

Данные и логика подключаются обычными `<script>`, поэтому достаточно любого
статического сервера:

```bash
python3 -m http.server 8088 --bind 127.0.0.1
```

Затем открыть <http://127.0.0.1:8088/> из каталога `solution/mvp`.
Сборка, зависимости и backend не нужны.

## Файлы

| Файл | Назначение |
|------|------------|
| `index.html` | Разметка оболочки, панели виджета, отчёта и набор inline SVG-иконок |
| `styles.css` | Визуальная система: токены, оболочка, таблица, состояния виджета |
| `app.js` | Presentation layer: рендер таблицы, состояния виджета, отчёт, применение и откат |
| `widget-script.js` | Доменная логика нормализации и валидации строки (`window.LPC`) |
| `data.js` | 30 записей типа APPLICATION из `data/raw/dev-sample.csv` |

## Что действительно работает

Интерактивны только перечисленные элементы. Остальная оболочка — проводник, rail,
кнопки вида в toolbar — статична и намеренно не выглядит кликабельной.

- **Поиск** в toolbar — фильтрует таблицу по названию проекта, компании, городу,
  ИНН, идентификатору заявки и email заявителя.
- **Чекбоксы строк** и чекбокс в шапке — отмечают строки. Отметка пока не влияет
  на область проверки: проверка всегда выполняется по всем записям.
- **Проверить данные** — запускает нормализацию и валидацию всех записей.
- **Посмотреть изменения** — открывает отчёт по правилам.
- **Применить все N** — применяет все предложенные изменения к данным в памяти.
- **Отменить изменения** — возвращает исходные значения.
- **Свернуть панель виджета** и вернуть её вертикальной кнопкой у правого края.
- Отчёт закрывается по Escape; Tab и Shift+Tab не выходят за его пределы.

## Состояния виджета

1. **До запуска** — заголовок, одна строка пояснения, источник и число записей,
   один primary-CTA `Проверить данные`. `Настройки проверки` — disabled, экрана нет.
2. **Выполняется** — спиннер и disabled-кнопка.
3. **Результат** — `30 записей · 153 предложения` и три строки:
   безопасные исправления, требуют внимания, блокирующие ошибки.
4. **Применено** — `153 изменения в 30 записях`, разбивка по правилам и одна
   кнопка `Отменить изменения`.

Отчёт листается по одному правилу на страницу (`1 из 8`) и показывает
`Заявка / Было / Стало`. Массовая кнопка содержит точное число действий.

## Правила проверки

Восемь правил, по одному на страницу отчёта. Числа — фактический результат на
текущих 30 записях.

| Правило | Что делает | Изменений |
|---------|------------|-----------|
| Email компании | нижний регистр, удаление пробелов и `mailto:` | 23 |
| Телефон компании | единый формат `+7…` | 24 |
| ИНН компании | удаление префикса «ИНН» и пробелов | 16 |
| Город | нормализация и транслитерация известных вариантов | 9 |
| ФИО заявителя | единый регистр | 17 |
| Бюджет | очистка валюты, `млн`/`тыс.` в число | 24 |
| Дата начала | формат `ГГГГ-ММ-ДД` | 21 |
| Дата окончания | формат `ГГГГ-ММ-ДД` | 19 |

Итого 153 предложения, 12 замечаний уровня `info` (город латиницей),
0 блокирующих ошибок. На выбранных записях нет блокирующих ошибок, поэтому
валидатор находит преимущественно нормализуемые расхождения форматов.

Повторный запуск после применения предлагает 0 изменений: сценарий идемпотентен.

## Чего пока нет

Не реализованы обязательные части сквозного сценария из
[`docs/core/PROJECT.md`](../../docs/core/PROJECT.md): поиск дублей, matching со
справочниками и confidence, создание связей, выбор шаблона проекта, создание
задач, рекомендации исполнителей и итоговый отчёт запуска.

Известные ограничения текущей проверки, зафиксированные в
[аудите](../../research/mvp-ui-audit-2026-09-06.md):

- выбор строк не сужает область проверки;
- нельзя принять или отклонить отдельное действие — только все сразу;
- отсутствующие обязательные значения не считаются ошибкой;
- несуществующая календарная дата (`31.02.2027`) молча превращается в соседнюю;
- значения вида `2027-01-01T00:00:00Z` считаются уже нормализованными и остаются
  в таблице с временем.

## Перенос в реальный Widget Script

`widget-script.js` не зависит от DOM и экспортирует функции через `window.LPC`,
поэтому нормализацию можно перенести в Widget Script MWS Tables, заменив
`data.js` на чтение записей через API таблицы и оставив `app.js` как
демонстрационный слой.
