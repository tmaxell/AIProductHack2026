# Mock MVP — Project Launch Copilot для MWS Tables

Интерактивная mock-страница, имитирующая конечную реализацию Widget Script в MWS Tables.
Показывает: данные из dev-выборки, запуск первой валидации таблицы, предложение нормализаций.

## 🚀 Быстрый запуск

Самый простой способ (потребуется локальный HTTP-сервер, т.к. данные загружаются через `fetch`/`script`):

```bash
cd /workspace/mws_tables/mvp
python3 -m http.server 8088
# откройте http://localhost:8088/
```

Или просто откройте `index.html` в браузере двойным кликом
(если браузер разрешит загрузку локальных `data.js`/`app.js`; надёжнее через сервер).

## 📁 Файлы

| Файл | Назначение |
|------|------------|
| `index.html` | Разметка страницы (layout MWS Tables, таблица, панель виджета, модалка скрипта) |
| `styles.css` | Оформление в стилистике MWS Tables (акцент — фиолетовый, 3-колоночный layout) |
| `widget-script.js` | Имитация реального Widget Script: нормализация + валидация (`window.LPC`) |
| `app.js` | Логика UI: рендер таблицы, запуск валидации, применение нормализаций |
| `data.js` | 30 APPLICATION-записей из `dev-sample.csv` |

## 🧪 Что делает mock

1. **Загрузка данных** — 30 заявок из dev-выборки отображаются в таблице.
2. **Запуск валидации** — кнопка **«Выполнить»** / **«▶ Выполнить скрипт»**:
   - нормализует email, телефоны, ИНН, города, ФИО, бюджеты, даты;
   - считает качество записи (ошибки / предупреждения / замечания);
   - вычисляет долю «готово к запуску» (порог 70% из ФТ).
3. **Правая панель (результат)** — показывает ТОЛЬКО:
   - компактные метрики (готовность %, ошибки, предупреждения, число преобразований);
   - список выполненных преобразований **по типам** (Email, Телефон, ИНН, Город, ФИО, Бюджет, Дата);
   - кнопку **«Подробнее → полный отчёт»**.
4. **Полный отчёт (кнопка «Подробнее»)** — модальное окно с **пагинацией по правилу/критерию валидации**:
   - каждая страница = одно правило (напр. «Email компании»);
   - структурированная таблица **«Было → Стало»** по всем затронутым записям с колонками Заявка / Было / → / Стало / Причина;
   - кнопки ← → для листания по правилам (1/8, 2/8, …);
   - кнопка **«✓ Применить все нормализации»** в футере.
5. **Применение** — вносит правки в данные идемпотентно; после применения панель показывает «✓ Все N преобразований применены» и кнопку «Отменить».

## 🔀 Пагинация полного отчёта — по каким правилам

8 правил (критериев) валидации, по одному на страницу:

| # | Правило | Тип преобразования |
|---|---------|--------------------|
| 1 | Email компании | приведение к нижнему регистру, удаление пробелов |
| 2 | Телефон компании | единый формат |
| 3 | ИНН компании | удаление префикса «ИНН», пробелов |
| 4 | Город | нормализация / транслитерация |
| 5 | ФИО заявителя | единый регистр |
| 6 | Бюджет | очистка валюты, числовой вид |
| 7 | Дата начала | формат ГГГГ-ММ-ДД |
| 8 | Дата окончания | формат ГГГГ-ММ-ДД |

## 🔌 Как подключить к реальному Widget Script

`widget-script.js` написан так, чтобы логику нормализации можно было перенести в реальный
Widget Script MWS Tables:
- экспорт через `window.LPC = { normalizeEmail, normalizePhone, ..., validateRow }`;
- в реальном виджете используйте `base.getTable()` / `selectRecordsAsync()` (см. блок кода в модалке).

## 📊 Ожидаемый результат валидации (на выбранных 30 записях)

- Записей: **30**
- Нормализаций предложено: **~150**
- Доля «готово к запуску»: **~93–100%** (после применения нормализаций)
- Замечаний (лат. города и т.п.): **12**

> Честная оценка: выбранные первые 30 записей не содержат блокирующих ошибок,
> поэтому валидатор выявляет в основном *нормализуемые* проблемы (форматы). 
> Для полноты демонстрации блокирующих ошибок можно расширить выборку записями с латиницей/дублями.

## 🧹 Замечания по идемпотентности
Повторное нажатие «Выполнить» после применения нормализаций не изменит данные повторно —
нормализованные значения проходят валидацию как корректные.
