# Спецификация виджетов нормализации данных MWS Tables

## Обзор

Набор из 8 скриптов для нормализации данных в таблицах MWS/AITable. Каждый виджет решает одну задачу и может запускаться независимо.

---

## Виджеты

### #01 Базовая нормализация
**Файл:** `widgets/01-normalize-basic.js`

**Что делает:**
- Ё → Е (Ковалёва → Ковалева)
- Неразрывные пробелы (U+00A0) → обычные пробелы
- Табы, переносы строк → пробелы
- Кавычки «»""„" → ""
- Тире –— → дефис -
- Множественные пробелы → один
- Пробелы в начале/конце → удалить

**Когда использовать:** Первый этап очистки любых текстовых данных.

---

### #02 Нормализация Email
**Файл:** `widgets/02-normalize-emails.js`

**Что делает:**
- Приводит к нижнему регистру (TEST@EXAMPLE.COM → test@example.com)
- Убирает префикс `mailto:`
- Убирает пробелы внутри email
- Убирает завершающую точку с запятой (;)
- Флаг для некорректных email (не проходят валидацию)

**Умная детекция:** Ищет поля по названию (`email`, `почт`, `mail`) и по содержимому (наличие @).

---

### #03 Нормализация телефонов
**Файл:** `widgets/03-normalize-phones.js`

**Что делает:**
- 89991234567 → +79991234567
- 9991234567 → +79991234567 (добавляет +7)
- +79991234567 → +79991234567 (оставляет как есть)
- Маскированные номера (***1234) → флаг "номер маскирован"
- <10 цифр → флаг "<10 цифр"
- >12 цифр → флаг ">12 цифр"
- Не-РФ формат → флаг "не-РФ формат"

**Умная детекция:** Ищет поля по названию (`phone`, `тел`, `телефон`) и по содержимому (10-12 цифр в >60% записей).

---

### #04 Нормализация дат
**Файл:** `widgets/04-normalize-dates.js`

**Что делает:**
- YYYY-MM-DD (2024-01-15) → 2024-01-15 (оставляет)
- DD.MM.YYYY (15.01.2024) → 2024-01-15
- DD.MM.YY (15.01.24) → 2024-01-15
- N месяц ГГГГ (15 января 2024) → 2024-01-15
- Неверные компоненты (месяц >12, день >31) → флаг
- Нераспознанный формат → флаг

**Умная детекция:** Ищет поля по названию (`date`, `дата`, `start`, `end`) и по паттернам дат.

---

### #05 Нормализация ФИО
**Файл:** `widgets/05-normalize-fio.js`

**Что делает:**
- иванов иван → Иванов Иван (Title Case)
- иванов иван иванович → Иванов Иван Иванович
- ИВАНОВ ИВАН → Иванов Иван (нижний + Title Case)
- Иванов И.И. → Иванов И.И. (инициалы сохраняет)
- Одно слово → флаг "не 2-3 части"
- >3 слов → флаг "не 2-3 части"

**Умная детекция:** Ищет поля по названию (`fio`, `фио`, `имя`, `фамил`) и по структуре (2-3 слова).

---

### #06 Нормализация городов
**Файл:** `widgets/06-normalize-cities.js`

**Что делает:**
- екб → Екатеринбург (алиасы)
- мск → Москва, спб → Санкт-Петербург
- г Москва → Москва (убирает "г ")
- МОСКВА → Москва (Title Case)
- Латиница (Moscow) → флаг "латиница"
- Не город (цифры, символы) → флаг "не город"

**Словарь алиасов:** екб, нск, спб, мск, члб, уренб, казнь, нн, уфа, самара, омск, рдн, красноярск, воронеж, пермь, волгоград, краснодар, саратов, тюмень, тольятти, иж, барнаул, ульяновск, иркутск, хабаровск, ярославль, владивосток.

---

### #07 Нормализация компаний
**Файл:** `widgets/07-normalize-companies.js`

**Что делает:**
- ООО "Ромашка" → Ромашка (убирает ОПФ)
- ИП Иванов → Иванов
- АО "Газпром" → Газпром
- ОАО, ЗАО, ПАО, ТОО, ЧП, ИЧП → убирает
- Убирает кавычки «», "", „"
- Приводит к Title Case (ромашка → Ромашка)

**Умная детекция:** Ищет поля по названию (`company`, `компан`, `org`, `контрагент`).

---

### #08 Нормализация сумм
**Файл:** `widgets/08-normalize-amounts.js`

**Что делает:**
- 1.5 млн → 1500000
- 150 тыс → 150000
- 1000 руб → 1000
- 5000₽ → 5000
- $100 → 100 (только число, валюта удаляется)
- 1,5 млн (запятая) → 1500000
- Нераспознанный формат → флаг "не сумма"

**Умная детекция:** Ищет поля по названию (`budget`, `сумм`, `price`, `млн`, `тыс`).

---

## Как использовать

### Запуск виджета

1. Открыть таблицу в MWS Tables
2. Добавить виджет «Скрипт»
3. Вставить код из файла виджета
4. Нажать «Выполнить»
5. Следовать инструкциям в чате

### Рекомендуемая последовательность

Для полной очистки данных:

```
1. #01 Базовая (ё→е, пробелы, кавычки)
2. #02 Email
3. #03 Телефоны
4. #04 Даты
5. #05 ФИО
6. #06 Города
7. #07 Компании
8. #08 Суммы
```

**Почему такой порядок:**
- #01 чистит "мусор" для лучших результатов остальных
- #02-#08 независимы, можно в любом порядке

## Режимы работы

### Обычный (быстрый)
- Preview: 15 строк в чате
- Применение: сразу после подтверждения
- Когда: массовая обработка, доверяете правилам

### Визуальный (с проверкой)
- Файл: `01-normalize-basic-visual.js`
- Требует: 4 столбца для каждого поля (_OLD, _CHANGE, _NEW, _APPLY)
- Preview: все строки в таблице
- Контроль: можно отменить в любых строках
- Когда: важные данные, нужна проверка

## Флаги проблемных данных

Все виджеты помечают проблемные значения:

| Флаг | Причина | Что делать |
|------|---------|------------|
| `некорректный email` | Нет @ или домена | Проверить вручную |
| `номер маскирован` | Есть * в номере | Запросить полный номер |
| `<10 цифр` | Мало цифр | Дополнить код страны |
| `формат даты` | Нераспознанный формат | Уточнить формат |
| `латиница` | Город на английском | Перевести |
| `не сумма` | Текст вместо числа | Ввести число |

## Умная детекция полей

Каждый виджет (#02-#08) **сам находит поля** для обработки:

### 1. По названию поля
| Виджет | Ищет в названии |
|--------|----------------|
| #02 Email | `email`, `почт`, `mail` |
| #03 Телефоны | `phone`, `тел`, `телефон` |
| #04 Даты | `date`, `дата`, `start`, `end` |
| #05 ФИО | `fio`, `фио`, `имя`, `фамил` |
| #06 Города | `city`, `город` |
| #07 Компании | `company`, `компан`, `org` |
| #08 Суммы | `budget`, `сумм`, `price`, `млн` |

### 2. По содержимому (анализ 20 записей)
| Виджет | Паттерн |
|--------|---------|
| #02 Email | Есть `@` в >50% записей |
| #03 Телефоны | 10-12 цифр в >60% записей |
| #04 Даты | Формат YYYY-MM-DD или DD.MM.YYYY в >50% |
| #05 ФИО | 2-3 слова в >50% |
| #06 Города | Слова из словаря алиасов |
| #07 Компании | Есть ОПФ (ООО, ИП) в названии |
| #08 Суммы | Есть `млн`, `тыс`, `руб` в значении |

## Примеры использования

### Сценарий 1: Быстрая очистка
```
Запустить: #01 → #02 → #03
Ввод: да (подтверждение)
Итог: ~5 минут на 1000 строк
```

### Сценарий 2: Тщательная проверка
```
1. Создать столбцы (_OLD, _NEW, _APPLY)
2. Запустить: #01-visual
3. Проверить в таблице, изменить флаги
4. Ввести: готово
Итог: ~15 минут на 100 строк
```

### Сценарий 3: Только критичные поля
```
Запустить: #06 (Города) + #07 (Компании)
Режим: Визуальный
Итог: Только важные данные проверены
```

## Ограничения

- API MWS Tables не позволяет скриптам создавать столбцы
- Визуальный режим требует ручного создания 4 столбцов на каждое поле
- Максимальный размер партиции: 100 записей
