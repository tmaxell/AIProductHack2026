# Solution

Здесь разрабатывается фактическое решение для MWS Tables: исходный код Widget Script, тесты, конфигурация и техническая инструкция по установке. Требования и ограничения решения находятся в [`docs/core/PROJECT.md`](../docs/core/PROJECT.md).

## План реализации

[`PLAN.md`](PLAN.md) — утверждённый рабочий план базового технического минимума (без LLM и без «углублённой» интеллектуальной фичи, см. план для обоснования). Разбор каждого шага (вход/выход/контракты функций) — в [`plan/`](plan/README.md).

Разработка и тестирование логики ведутся локально через mock-SDK (`solution/devtools/`), без доступа к реальному пространству MWS Tables — см. `PLAN.md#локальная-разработка-и-тестирование-без-доступа-к-mws`.

## Как запустить локально прямо сейчас (Milestones 1–7 готовы)

Нужен Node.js (проверено на v26; подойдёт и более старая LTS-версия, зависимостей нет вообще — только `node:fs`/`node:http`/`node:readline`).

```bash
# 1. Собрать локальный seed из data/raw/dev-sample.csv (один раз, пересоздаётся по требованию)
node solution/devtools/seed.js

# 2. Прогнать интерактивно — мастер настройки спросит ID таблиц/полей прямо в терминале
#    (на вопросы про ID таблиц отвечайте любыми уникальными строками — в mock-режиме это просто ключи,
#    на вопросы про поля — точными именами полей, которые предложит подсказка в квадратных скобках)
node solution/devtools/run-local.js --limit 20

# 3. Проверить идемпотентность — повторный запуск на результате первого не должен ничего применять заново
node solution/devtools/run-local.js --seed data/derived/local-run-result.json --limit 20
```

Полезные флаги `run-local.js`: `--limit N` (обработать только первые N заявок — удобно для ручных тестов), `--html` (после прогона поднять локальный просмотрщик в браузере), `--reconfigure` (сбросить кэш конфигурации и пройти мастер заново), `--answers <file.json>` (скриптованный режим без участия человека — см. `solution/devtools/fixtures/demo-answers.json` как пример готового набора ответов для интерактивного мастера).

Сейчас реализованы Milestones 1–7: mock-SDK/seed, мастер конфигурации, нормализация (email/телефон/даты/бюджет/города/ФИО/названия компаний), движок preview/apply с ручным разбором неоднозначных случаев, дедуп и сопоставление со справочниками (компании/сотрудники/дубли заявок), классификация типа/приоритета, базовые проверки аномалий. Проверено на всех 6800 заявках dev-выборки: полный прогон всех 4 фаз занимает ~1–1.6с, идемпотентность подтверждена (3 прогона подряд — 0 новых действий). Milestones 8–11 (задачи по шаблону, назначение исполнителей, запуск проекта, сборка/тесты) — по плану, ещё не реализованы.

Журнал того, что реально прогонялось и какие баги были найдены/исправлены по ходу — [`docs/TEST-RESULTS.md`](docs/TEST-RESULTS.md), обновляется по мере прохождения каждого milestone.

## Сборка в единый файл для вставки в MWS

```bash
node solution/build/build.js               # собирает solution/dist/widget.bundle.js
node --check solution/dist/widget.bundle.js  # синтаксис
node solution/devtools/verify-bundle.js --limit 20   # реальный прогон бандла в песочнице без require/module (эмуляция браузера MWS)
```
`solution/dist/widget.bundle.js` — тот самый файл, который в реальном MWS Tables вставляется целиком в редактор Script Widget (см. обсуждение установки выше/в чате). Коммитится в репозиторий как готовый артефакт, а не только генерируется — регенерируйте после любой правки `solution/src/`.
