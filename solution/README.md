# Solution

Здесь разрабатывается фактическое решение. Требования и ограничения находятся в
[`docs/core/PROJECT.md`](../docs/core/PROJECT.md).

## Два независимых трека

| Трек | Где | Что это |
|---|---|---|
| **Widget Script** | `solution/src`, `build`, `devtools`, `dist`, `plan`, `docs` | Код, который встраивается в реальное пространство MWS Tables и собирается в один файл `dist/widget.bundle.js`. Без зависимостей и без сборщика. |
| **Веб-приложение** | [`solution/webapp/`](webapp/README.md) | Самостоятельное приложение: статический фронтенд за nginx, Fastify + TypeScript backend, персистентный Change Set API и необязательное backend-only объяснение Groq, всё в Docker. |

Треки разрабатываются параллельно и **разделены на уровне репозитория**:

- они не делят исходный код и не импортируют друг друга;
- задача одного трека не изменяет файлы другого;
- у каждого свои зависимости, сборка, запуск и документация.

Общими остаются только материалы уровня репозитория: `docs/core/`, `data/`,
`research/` и правила в `AGENTS.md`.

Причина разделения: у виджета жёсткие ограничения среды MWS Tables — один файл,
никаких зависимостей, никакого сетевого доступа без явного действия
пользователя. Веб-приложение этих ограничений не имеет. Смешивание кода
подчинило бы его ограничениям виджета либо сломало бы виджет.

На ветке с веб-приложением каталогов Widget Script может не быть: его трек
ведётся на своей ветке и мерджится отдельно.
