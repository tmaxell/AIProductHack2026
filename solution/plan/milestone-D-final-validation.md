# Milestone D — финальная валидация в реальной MWS

Статус: **реальная MWS, когда появится доступ**. Финальный шаг всего плана.

## Зачем

Доказать на самой платформе (не только на mock-SDK), что весь сквозной сценарий работает, включая идемпотентность повторного запуска — это и есть формальная приёмка плана.

## Вход

- Пространство после Milestone C (8 датасетов, заполненные справочники, чистые «Заявки»).
- `solution/dist/widget.bundle.js` (Milestone 11), вставленный в реальный Script Widget на таблице «Заявки» — **без единого изменения кода логики**, только подключение к настоящим `space`/`input`/`output` вместо mock.

## Что делает

1. Первый прогон на подвыборке 50–100 заявок (через view-фильтр в MWS): проходит весь мастер настройки (Milestone 2) один раз, смотрит preview на каждом шаге (Milestones 3–7), подтверждает, смотрит созданные Проекты/Задачи/назначения (Milestones 8–10) и итоговую сводку.
2. Затем — прогон на всех 6800 заявках.
3. Повторный прогон (без изменения входных данных) на той же подвыборке — сверяет `RunSummary` (Milestone 10) и запись в **Copilot Runs**: все «созидающие» счётчики должны быть `0`.
4. Лёгкая ручная сверка качества (не заменяет эталонную разметку организаторов, см. `data/AGENTS.md`): просмотр ~50–80 предложений по дублям (Milestone 5) и классификации (Milestone 6) из прогона, ручной agree/disagree.

## Выход

### `solution/docs/TEST-RESULTS.md`

- Результаты прогона на 50–100 и на всех 6800 (число проверено/исправлено/связано/дублей/аномалий/задач/проектов — из реальных `RunSummary`).
- Явное подтверждение идемпотентности (лог **Copilot Runs**, две записи подряд, вторая — с нулевыми созидающими счётчиками).
- Таблица agree/disagree по ~50–80 вручную проверенным предложениям, с явной пометкой: **это внутренняя прикидка команды, не официальная оценка организаторов**.

## Критерий готовности

- Все пункты «Что делает» выполнены и задокументированы.
- Ни одна ошибка выполнения не осталась необъяснённой (см. `AGENTS.md`: ошибки должны обрабатываться и показываться пользователю понятно — если что-то падает без понятного сообщения, это баг, который нужно закрыть до сдачи).
- `STATUS.md` и `research/product-materials-interim.md` (разделы 3–4, 7–15) обновлены по факту реализации — отдельная задача, но нужно не забыть перед сдачей.
