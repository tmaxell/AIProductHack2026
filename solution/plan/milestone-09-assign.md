# Milestone 9 — round-robin назначение

Статус: локально, чистая функция. Сознательно простая — см. `../PLAN.md#контекст` (нагрузка/навыки/отсутствия/SLA вне скоупа).

## Зачем

Каждой создаваемой задаче (Milestone 8) нужен исполнитель. Базовый вариант по условиям кейса — round-robin, без продвинутой оптимизации.

## Вход

- `TaskDraft` (в первую очередь важно поле `requiredRole`; `dueDate`, если уже известен на момент назначения — для проверки отпуска).
- Список активных Сотрудников (`active === true`) с нужной `role`, отсортированный стабильно (по `employee_id`, чтобы ротация была детерминированной между прогонами).
- Текущее состояние указателя ротации по роли — `CopilotConfig.assignPointers[role]` (id последнего назначенного сотрудника этой роли).

## Что делает

1. Фильтрует Сотрудников: `active === true` и `role === task.requiredRole`.
2. Если список пуст → `employeeId: null`, `reason: "нет активного сотрудника с ролью <role>"` (флаг `NEEDS_MANUAL_ASSIGNMENT` ставится на задачу в Milestone 10).
3. Иначе — находит в отсортированном списке позицию сотрудника из `assignPointers[role]`, берёт следующего по кругу (если указателя ещё нет — берёт первого).
4. Если у выбранного сотрудника `dueDate` задачи попадает в `[absent_from, absent_to]` — пропускает его и берёт следующего по кругу (не более одного полного круга, иначе — как «нет доступного», с этим же reason).
5. **Не мутирует конфиг напрямую** — возвращает новое значение указателя, вызывающий код (`launch.js`, Milestone 10) копит все изменения указателей за прогон и сохраняет их в Config одним вызовом в конце (через `config.js` из Milestone 2).

Пример:

```js
{
  employeeId: "emp_0042",
  reason: "round-robin: следующий активный 'Архитектор' после emp_0031",
  newPointerState: { "Архитектор": "emp_0042", /* остальные роли без изменений */ }
}
```

## Критерий готовности

- Тест: N сотрудников одной роли, N×3 задач подряд → каждый сотрудник получает ровно 3 задачи (равномерность).
- Тест: сотрудник в отпуске на дату `dueDate` задачи пропускается, следующий круг находит доступного.
- Тест: роль без единого активного сотрудника → `employeeId: null` без исключения, с понятным `reason`.
- Указатель ротации переживает повторный запуск (сохраняется в Config, не сбрасывается в начале каждого прогона).
