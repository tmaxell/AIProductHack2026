# Milestone 11 — сборка и юнит-тесты

Статус: локально, замыкает разработку без доступа к MWS.

## Зачем

MWS Script Widget принимает ровно один код-блок в редакторе — нужно уметь и разрабатывать модульно (для читаемости и тестируемости), и получить на выходе один файл для вставки. Плюс — формальное доказательство качества (тесты, идемпотентность) до всякого доступа к реальному пространству.

## Вход `build.js`

Все файлы `solution/src/lib/*.js` (в явном порядке зависимостей: `util.js` → `config.js` → `normalize.js` → `match.js` → `classify.js` → `anomalies.js` → `tasks.js` → `assign.js` → `launch.js` → `report.js` → `preview.js`) + `solution/src/widget/main.js` последним.

## Что делает `build.js`

Простая конкатенация файлов в указанном порядке (без транспиляции/минификации — не нужно, код и так плоский ES-синтаксис) в один файл. Каждый модуль обязан заканчиваться строкой вида:

```js
if (typeof module !== 'undefined') module.exports = { normalizeEmail, normalizePhone, ... };
```

— под Node (`require`, тесты, `devtools/run-local.js`) этот блок выполняется и функции становятся доступны через `require`; после конкатенации в браузере/MWS `module` не определён, блок просто пропускается, но сами объявления функций (`function normalizeEmail(...) {...}`) остаются в общей области видимости бандла.

## Выход `build.js`

- `solution/dist/widget.bundle.js` — единственный файл, который реально вставляется в редактор Script Widget в MWS (Milestone C/D).
- Команда: `node solution/build/build.js` (без аргументов, без внешних зависимостей — только `node:fs`).

## Вход тестов

- Все экспортируемые функции `solution/src/lib/*.js`.
- Фикстуры — короткие JSON-выдержки **реальных** строк `dev-sample.csv` (значения, не сам файл), с указанием происхождения (номер строки/`row_id`), лежат в `solution/tests/fixtures/*.json`. `data/raw/` при этом не трогаем — копируем только нужные значения в фикстуры.

## Что делает тестовый набор

`node --test solution/tests` (встроенный раннер Node, без новых зависимостей):
- по одному `*.test.js` на модуль (`normalize.test.js`, `match.test.js`, `classify.test.js`, `anomalies.test.js`, `tasks.test.js`, `assign.test.js`, `preview.test.js`) — юнит-тесты на чистые функции, критерии готовности перечислены в файлах соответствующих milestone'ов;
- один сквозной `idempotency.test.js`: прогоняет `run-local.js` (через `devtools/run-local.js --answers fixture.json`, см. Milestone 1) дважды подряд на одном `local-seed.json` и сравнивает вторую `RunSummary` (Milestone 10) — все «созидающие» счётчики обязаны быть `0`.

## Выход тестов

- Код выхода процесса `0` при всех тестах пройденных, ненулевой при провале любого — этого достаточно, отдельный отчёт не нужен (стандартный вывод `node --test`).

## Критерий готовности

- `node --test solution/tests` — всё зелёное.
- `node solution/build/build.js` отрабатывает без ошибок и производит непустой `dist/widget.bundle.js`.
- `node -e "require('./solution/dist/widget.bundle.js')"` не падает с синтаксической ошибкой — минимальная проверка валидности бандла как JS (сам вызов `run()` внутри не произойдёт, т.к. `typeof space === 'undefined'` вне MWS — это ожидаемо и корректно).

## Демонстрация (обязательный шаг перед переходом к следующему milestone)

Полный прогон на всех 6800 заявках через `run-local.js` (не только подвыборка): итоговая сводка, время выполнения (проверка «быстро», см. планку качества в Milestones 3/5), и вывод `node --test solution/tests` целиком.
