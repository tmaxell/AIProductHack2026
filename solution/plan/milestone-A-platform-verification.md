# Milestone A — проверка платформы

Статус: **реальная MWS, когда появится доступ**. Выполняется первым из всего, что трогает настоящее пространство — раньше создания реальных таблиц (Milestone C).

## Зачем

Публичная документация AITable, на которой основана MWS Tables, местами противоречива и не проверена в конкретном раздатом пространстве (см. `../PLAN.md#важная-оговорка-по-платформе`). Прежде чем создавать реальные Link-поля и писать в них, нужно знать, как это работает на самом деле.

## Вход

- Доступ (логин/URL) к раздатому пространству MWS Tables — единственное, чего сейчас не хватает для этого шага.
- Собственный тестовый (одноразовый, потом удаляемый) датасет внутри этого пространства.

## Что делает

Вручную, через реальный редактор Script Widget, прогоняет минимальные проверочные сниппеты и фиксирует ответы на конкретные вопросы:

| # | Вопрос | Как проверить |
|---|---|---|
| 1 | Существует ли `space.getActiveDatasheetAsync()`? | вызвать и залогировать результат/ошибку |
| 2 | Точная форма `property` для `createFieldAsync` с типами `OneWayLink`/`TwoWayLink` (обязательные поля: `foreignDatasheetId`, `brotherFieldId` и т.п.)? | создать тестовое Link-поле между двумя тестовыми датасетами, залогировать успех/ошибку и итоговую `field.property` |
| 3 | Реальный формат cell value Link-поля при чтении (`record.getCellValue`) и при записи (`updateRecordAsync`) — массив id-строк или массив объектов `{id}`? | записать вручную одну связь через UI, прочитать её скриптом; затем записать скриптом, прочитать через UI |
| 4 | Лимиты размера батча `getRecordsAsync`/`createRecordsAsync`/`updateRecordsAsync` | прогнать батч нарастающего размера (10/100/500/1000), зафиксировать, где начинаются ошибки/усечение |
| 5 | Поведение `output.table` — лимит строк/столбцов, как рендерится длинный текст | вывести таблицу на 50/200 строк, посмотреть визуально |
| 6 | Есть ли что-то персистентное между запусками кроме `localStorage` (например, снятие/переустановка виджета не теряет ли настройки)? | сохранить тестовое значение, закрыть/переоткрыть вкладку, переустановить виджет |

## Выход

### `solution/docs/PLATFORM-NOTES.md`

Один файл, по одному разделу на вопрос из таблицы выше, с фактическим ответом (не предположением) и явной пометкой, **какие места в коде** (`solution/devtools/mock-sdk.js`, конкретные строки в `lib/match.js`/`lib/tasks.js`, где пишутся Link-поля) нужно поправить, если реальность разошлась с рабочей гипотезой, заложенной в Milestones 1–11.

## Критерий готовности

- Все 6 вопросов из таблицы имеют зафиксированный фактический ответ (не «предположительно», а «проверено на дату X»).
- Тестовый датасет, использованный для проверки, удалён из пространства после того как ответы задокументированы.
