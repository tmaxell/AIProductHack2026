# AI Product Hack 2026 — Project Launch Copilot

Командный репозиторий решения для автоматизации подготовки и запуска проектов в MWS Tables.

## С чего начать

1. Прочитать [описание проекта и кейса](docs/core/PROJECT.md).
2. Проверить [текущий статус и открытые вопросы](STATUS.md).
3. Для анализа использовать материалы из `data/`, не изменяя исходные файлы.
4. Исследовательские результаты сохранять в `research/`, фактическую реализацию — в `solution/`.

Агенты дополнительно следуют [AGENTS.md](AGENTS.md).

## Структура

```text
.
├── AGENTS.md          # общие правила для coding agents
├── STATUS.md          # актуальный контекст и открытые вопросы
├── docs/core/         # стабильное описание проекта и терминов
├── data/              # исходные и производные данные
├── research/          # исследования, идеи и собранные требования
└── solution/          # код и документация фактического решения
    ├── webapp/        # самостоятельное веб-приложение (frontend + backend + Docker)
    └── …              # Widget Script для реальных MWS Tables
```

В `solution/` идут два независимых трека: встраиваемый Widget Script и
самостоятельное веб-приложение. Они не делят код и не изменяют файлы друг
друга — граница описана в [`solution/README.md`](solution/README.md).

## Актуальная реализация веб-приложения

В [`solution/webapp/`](solution/webapp/README.md) работает персистентный Change
Set API: draft-версии, решения пользователя, публикация, история, diff,
конфликты и компенсирующий rollback хранятся в SQLite. Необязательный
backend-only слой Groq объясняет выбранные действия после disclosure-preview и
явного согласия. Базовый сценарий не зависит от LLM.

Текущий прогресс и открытые вопросы поддерживаются в [`STATUS.md`](STATUS.md),
а архитектурные решения — в [`solution/webapp/docs/adr/`](solution/webapp/docs/adr/).

Новые каталоги и шаблоны добавляются только при появлении реальной потребности. Историю изменений хранит Git, поэтому не создаём копии файлов с названиями `final`, `latest` или `v2`.
